# Stage 1: supervised real-call test

This stage connects Chert/LiveKit media and xAI speech to a Claude controller on the real Calypso backend.
Recognition outcomes are deliberately controlled. They are **not** evidence that
face recognition works. Every outgoing frame has a stage 1 banner, and identity
cards say "Test profile". Use consenting teammates in these test calls.

  storage, Claude tool execution, confirmed enrollment, identity guards and call cleanup.
- The Claude gateway was deployed to Vultr and produced a real setup greeting;
  the probe call was ended without enrollment. LiveKit credentials also passed
  a read-only authentication check.

  and exactly one patient was verified afterward.
- Live Chert audio/video, xAI speech, group topology and real-call latency have
  **not** been verified. Do not mark them complete based on local tests.

## Credentials and patient

Caller-number linkage is wired into enrollment using the existing `Person.phone`
column; no schema migration was needed. A successful real Chert call lookup was
verified, and its number was linked to the existing confirmed Keanu profile.
Future setup calls resolve the caller from Chert automatically. The transport
needs its existing Chert CLI login for this lookup; if it is unavailable or the
caller uses email, enrollment continues with `phone: null`. No number is logged
or generated by Claude. Local checks: 43 media tests and 65 backend tests pass.

`agent/.env.local` is private and ignored by Git. The supplied backend token and
URL have been saved there. Merge remaining values from `agent/stage1.env.example`
without replacing existing credentials. Quote values that contain spaces.

LiveKit Cloud → select your project → **API keys** → select or create a key. Copy
its project WebSocket URL, API key and API secret:

```dotenv
LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your-project-api-key
LIVEKIT_API_SECRET=your-project-api-secret
XAI_API_KEY=your-xai-api-key
```

All three LiveKit values must come from the same project. No separate LiveKit
account login is needed by the Python worker once those values are configured.
The Chert CLI reads the same file and dispatches the named agent into that project.
See [LiveKit credentials](https://docs.livekit.io/agents/server/startup-modes/) and
[finding API keys](https://docs.livekit.io/reference/telephony/connectors-api/).

Create an xAI API key with access to the speech APIs and add it locally. This
adapter uses the documented [STT REST endpoint](https://docs.x.ai/developers/model-capabilities/audio/speech-to-text)
and [TTS endpoint](https://docs.x.ai/developers/model-capabilities/audio/text-to-speech).
It uses bounded batch transcription with an energy-based speech endpoint detector;
it does not establish streaming-STT or recall-latency performance.

The backend must have exactly one `Person` with `is_patient=true` before a call.
Create it through the backend's authenticated `/people` endpoint using the agreed
patient name, or have the backend teammate do so. The agent will not invent one.

## Setup call

Latest caller-display update: setup opens with “What's your name, and how do you
know Mary?” rather than addressing the caller as Mary. A successful save closes
with “Your introduction and memory have been saved. Thank you. Please hang up
now.” The final saved screen remains visible until the caller hangs up. Failure
or incomplete setup explicitly says nothing was saved.

Native automatic hangup is not enabled: the installed Chert CLI documents that
its login cannot call the native end-call API (that requires a browser session).
The current implementation uses the explicit hang-up instruction accepted in the
requested behavior; it does not silently disconnect the media or claim the phone
call has ended. See the installed CLI's `DEVELOPER_GUIDE.md`, errors section.

Live output is now 720×1280 portrait, H.264, 5 fps, with a 2.5 Mbps bitrate ceiling
and resolution-preserving encoding. Actual published dimensions/codec were checked
in LiveKit. Titles use 80 px text and body text 60 px; long speech captions page
without dropping words. Phone/Chert reception quality still needs a real-call
check. The legacy landscape renderer remains available for offline fixtures.
The updated code passes 40 media tests and 65 backend tests.

After the worker and Chert report ready, FaceTime **Video** the assigned line.
Keep one front-facing face visible in good light throughout setup. Give your name
and relationship, answer the shared-memory question, then confirm. The worker
collects three recent face crops at one-second intervals and submits them only
after confirmation. End the call after the saved-introduction message.

Face detection runs in a bounded subprocess to keep OpenCV's FFmpeg libraries
out of the LiveKit/PyAV process on macOS. No audio, images, or credentials are
printed by this adapter. A detector failure stops the test instead of enrolling
unvalidated camera frames.

The backend stores the actual transcript and crops. Claude extracts the name,
relationship and memory, reads them back, and its save tool fills the profile
only after an explicit yes. The backend rejects saving before confirmation or
without three current face crops. No local setup script drives this conversation. `data/stage1-enrollment.json` stores only the returned
person id for the next call; it survives worker restarts. Run from `agent/` in both
sessions so the default relative path refers to the same file.

Expected checks:

- [ ] Caller hears the greeting only after Chert signals `bridge_ready`.
- [ ] Setup questions are audible and captions appear on the agent tile.
- [ ] Backend has a new person with a face photo and a setup call with transcript lines.
- [ ] No/ambiguous confirmation does not enroll; silence reprompts once and ends setup.
- [ ] Missing/multiple faces prevent enrollment; call failure is logged and the backend call ends.

## Separate group call

Stop **both** terminal processes. Change `.env.local`:

```dotenv
CALYPSO_CALL_MODE=group
STAGE1_RECOGNITION=identified
```

Restart both commands. Form a group FaceTime containing the relative, patient
and Chert line using the manually supported call flow. Group-call joining and
automated dialing remain unverified; record what Chert actually supports.

The worker selects the first caller participant by default. Optionally configure
`STAGE1_PARTICIPANT_ID` to select an exact LiveKit identity from its logs. This mode
does not infer patient identity or call type from participant count. Only the
selected incoming video/audio is processed; this is an explicit stage 1 limitation.
Exactly one detected face is required in the processed frame. Composite grids
with multiple faces are skipped rather than assigned a controlled identity.

- [ ] Relative's selected camera produces "Test profile: Sarah" on the outgoing tile.
- [ ] Patient can read the card; one card remains visible for 6–10 seconds.
- [ ] Repeated frames do not cause duplicate cards within 60 seconds.
- [ ] Backend/dashboard receives `stage1.recognition`, `card.queued`, `card.shown` and transcript lines.
- [ ] Ending FaceTime closes the backend call and releases all media consumers.
- [ ] Repeat with `learning`: neutral card appears after three consecutive qualifying frames.
- [ ] Repeat with `uncertain`: no identity card is produced.

### Managed bridge audio requirement

The installed Chert CLI documents ending calls if no agent audio is heard within
10 seconds of `bridge_ready`. Normal group behavior requires silence. Neither
published silent audio nor the local tests proves this platform constraint solved.

There is no automatic group greeting in the Claude controller. It permits only
one newcomer question after debounced learning. Resolve Chert's timeout behavior
with Chert before accepting the production group workflow; do not treat published
silent audio as proof that the platform requirement is satisfied.

## Backend deployment

The gateway is deployed in `/root/HackUTA/backend` on Vultr, in the existing
`calypso-backend.service`. It reads `/root/HackUTA/.env`, which already contains
the Claude key. That key was never copied to the laptop. The original app was
backed up under `/root/calypso-gateway-backup.JTW8aB` before deployment.

The authenticated gateway endpoints are:

- `POST /agent/sessions`: explicit setup/group mode and selected participant.
- `POST /agent/sessions/{id}/events`: start, utterance, silence or camera frame.
- `POST /agent/sessions/{id}/end`: idempotent session/call cleanup.

Responses contain speech, cards and completion/enrollment metadata. Claude
requests backend tools; the server executes and validates them. There is no
arbitrary-URL, shell, or dialing tool. Session state is in memory: use one backend
worker, and reconnect calls after a backend restart. Model failures stop the
session rather than silently switching to a scripted conversation.
